# PII Guard — extension для Pi coding agent

Защита персональных данных при работе с coding-агентом
[Pi](https://github.com/earendil-works/pi): ПДн не уходят в LLM,
ответы деанонимизируются обратно, промпт-инъекции блокируются.

**Автор:** Крайнов Александр Витальевич — Fullstack/ML-разработчик

## Как это работает

```
пользователь
   │  «Иванов просил отправить отчёт на ivanov@mail.ru»
   ▼
input ────────► guardrails /scan ── инъекция? ── блок (до раскрытия /skill:!)
   │
   ▼
service /anonymize ── «[PERSON_1] просил отправить отчёт на [EMAIL_1]»
   │                  (vault в PostgreSQL: стабильные ID в рамках сессии)
   ▼
LLM (видит только плейсхолдеры)
   │  «[PERSON_1], отчёт отправлен на [EMAIL_1]»
   ▼
message_end ── service /deanonymize (по vault_key сессии)
   │
   ▼
пользователь ── «Иванов, отчёт отправлен на ivanov@mail.ru»
```

Перехватываемые события Pi:

| Событие | Что делает pii-guard |
|---|---|
| `input` | скан ввода на инъекции (**до раскрытия скиллов**), анонимизация ПДн |
| `tool_call` | маскирование ПДн в аргументах инструментов (`command`, `content`, …) |
| `tool_result` | скан вывода инструментов на инъекции + анонимизация ПДн в данных |
| `message_end` | деанонимизация ответа ассистента по vault-ключу сессии |
| `session_start/shutdown` | восстановление/сброс vault-ключа (переживает restart) |

Ключевые свойства:

- **Стабильные плейсхолдеры**: «Иванов» в любом сообщении сессии → всегда
  `[PERSON_1]`, поэтому LLM может ссылаться на него в многоходовых диалогах,
  а деанонимизация однозначна. Хранилище — PostgreSQL на стороне сервиса
  (TTL 24 ч, ключ сессии — uuid4).
- **Скиллы проверяются до раскрытия**: содержимое `/skill:...` сканируется
  на инъекции в сыром виде — вредоносный скилл не попадёт в контекст.
- **Инъекции в данных**: результат `read`/`fetch`/`bash` может содержать
  инструкции («ignore previous instructions…») — такие результаты
  помечаются ошибкой и не уходят в LLM.
- **Fail-open**: недоступность сервисов не ломает Pi (настраивается
  `PII_FAIL_OPEN=0` для строгого режима).

## Установка

### 1. Поднять сервисы (из корня репозитория)

```bash
docker compose up -d --build
# anonymization: http://localhost:8001 (vault в PostgreSQL)
# guardrails:    http://localhost:8002
```

### 2. Установить extension

```bash
# глобально для всех проектов:
mkdir -p ~/.pi/agent/extensions/pii-guard
cp -r harness/* ~/.pi/agent/extensions/pii-guard/
cd ~/.pi/agent/extensions/pii-guard && npm install

# или локально для проекта:
mkdir -p .pi/extensions && cp -r harness .pi/extensions/pii-guard
```

Pi подхватит extension автоматически (проверить: `/pii-status` в чате).

### 3. Переменные окружения (опционально)

| Переменная | Дефолт | Описание |
|---|---|---|
| `PII_SERVICE_URL` | `http://localhost:8001` | сервис анонимизации |
| `GUARDRAILS_URL` | `http://localhost:8002` | guardrails |
| `PII_TIMEOUT_MS` | `15000` | таймаут HTTP-запросов |
| `PII_FAIL_OPEN` | `1` | `0` = блокировать работу при недоступности сервисов |

## Команды в Pi

- `/pii-status` — статус: URL сервисов и текущий vault-ключ;
- `/pii-reset` — новая vault-сессия (сброс связи плейсхолдеров с данными).

## Тесты

```bash
cd harness && npm install && npx vitest run   # 16 тестов: round-trip,
                                              # стабильные ID, блок инъекций
                                              # в скилле и tool_result
```

## Приватность

- Текст с ПДн отправляется только на **свой** сервис анонимизации
  (self-hosted); в LLM уходит текст с плейсхолдерами.
- Связь «плейсхолдер → значение» хранится в вашем PostgreSQL
  (контейнер в docker-compose, наружу не выставлен).
- Оригинальный текст не логируется.
